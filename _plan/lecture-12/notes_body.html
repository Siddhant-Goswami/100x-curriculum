One tool call. Then an MCP server.

Two Python files, two steps.

Since Lecture 9 you have asked a model one question: which track should I choose? On its own, the model makes up the answer. On the Tool Bench you gave it a tool by clicking. Today you write that tool in Python, in two files from the c8-tools repo:

StepFileWhat it does
1tool_call.pyThe model asks for your function. Your code runs it. The model answers from the result.
2mcp_server.pyThe same function as an MCP server, so any app can use it.

Setup: pip install requests python-dotenv fastmcp, then a file called .env with one line: GROQ_API_KEY=your key.

01Step 1: the function

The answer lives in the curriculum sheet, one tab per track. A plain Python function reads one tab and returns each lecture with its tools:

{{cut:tool_call.py|# 1. A plain|# 2. A card}}

No model yet. Same track in, same list out, every time.

02Step 1: the card

The model can't see your function. It reads a card that describes it: a name, what it does, and what to pass in. The request to Groq is the one from Lecture 5 with one new field, tools.

{{cut:tool_call.py|# 2. A card|# 3. Ask.}}

03Step 1: the tool call

Send the question with the card. The model does not answer: it replies with a tool call, the name of your function and what to pass in. Your code runs the function and sends the result back. While the model keeps asking, the loop keeps running. When it stops asking, that reply is the answer.

{{cut:tool_call.py|# 3. Ask.}} 
$ python tool_call.py
The model asked for: get_lectures {'track': 'code'}
The model asked for: get_lectures {'track': 'no-code'}

Both tracks cover the same AI fundamentals and product-building milestones, but the code track teaches
implementation with Python, FastAPI, Gradio/Streamlit, Supabase and Groq, while the no-code track uses
visual tools like Google Stitch, AI Studio, Antigravity and Vercel for the same outcomes. …
  • The model never touched the sheet. It wrote a request. Your code did the work.
  • It asked twice, once per track, on its own.
  • Every tool it names is in the sheet, because it copied them from the result.

That is a tool call: the model asks, your code acts.

04Step 2: the MCP server

Your function lives inside tool_call.py. Another app can't use it there. An MCP server puts it at an address any app can reach. This is the whole file:

{{cut:mcp_server.py|import csv}}
  • The function is the same as step 1.
  • The card is gone. @mcp.tool writes it for you, from the function's name, its docstring and its type hint.
  • The Groq code is gone too. The server only runs the function. The app that connects brings the model.

Run it, leave it running, and in a second terminal ask the server what it offers, then call the tool:

$ python mcp_server.py                   # terminal 1

$ fastmcp list http://localhost:8000/mcp # terminal 2
Tools (1)

  get_lectures(track: str) -> dict
    Lists every lecture of one 100xEngineers Cohort 8 track, with the tools it uses. track is 'code' or 'no-code'.

$ fastmcp call http://localhost:8000/mcp get_lectures track=no-code
{
  "result": [
    "1. Orientation and State of AI 2026: None",
    "2. What is an interface; UI as the first interface: None",
    "3. PRD to UI design to frontend app: Google Stitch, Google AI Studio",
    …
  ]
}
CommandAsks the server
fastmcp listWhat can you do? The card comes back.
fastmcp callRun this one, with these arguments. The result comes back.

MCP changes where the function lives. It does not change the function.

Words from this lecture
Tool
A function your code runs when the model asks for it.
Card
The description of a tool that the model reads: its name, what it does, and what to pass in.
Tool call
The model's reply naming a tool and what to pass in. A request, not an action.
MCP server
Tools at an address, so any app can list them and call them.
FastMCP
The Python library that turns a function into an MCP server.
