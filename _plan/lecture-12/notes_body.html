Give the model a tool. Then give the tool an address.

The question from Lecture 9, answered in Python: one function, one tool call, a verifier, and an MCP server.

Since Lecture 9 you have asked a model one question: which track should I choose? In Lecture 10 it scored 1, then 5, then 7 out of 10, and still named Zapier. On the Tool Bench you gave it a tool by clicking. Today you write that tool in Python. Every step is one short file in the c8-tools repo, and every output below is from a real run on 14 November.

01The question and its golden pair

Which track should I choose in the 100xEngineers cohort?

The facts live in the curriculum sheet, one tab per track. Four rows of the code tab:

number  date             title                           tools
3       Sat 26 Sep 2026  Building UI: Design to Deploy   Python, Gradio or Streamlit, Hugging Face Spaces
5       Fri 09 Oct 2026  Building APIs and backend       Python, FastAPI, Render
7       Fri 16 Oct 2026  Connect backend to database     FastAPI, Supabase
13      Fri 20 Nov 2026  Retrieval-augmented generation  None

The rule: a tool counts only if the sheet names it. "None", "TBD" and "[TO NAME]" are not tools.

Before any model runs, read the Tools column of each tab yourself.

TrackTools the sheet names
CodePython, Gradio, Streamlit, Hugging Face Spaces, FastAPI, Render, Supabase, Tool Bench, Groq, FastMCP
No-codeGoogle Stitch, Google AI Studio, Antigravity, Supabase, Vercel, Tool Bench, Groq

That is the golden pair: the question, and the facts a right answer must stand on. The hard lines of the eval follow from it: it names the two real tracks, every tool it names is in the sheet, and none of Lecture 10's inventions appear (Zapier, Bubble, Webflow, JavaScript).

2246 tokens used

Right, three runs out of three, and no Zapier. In Lecture 10 the same paste still invented it, and the golden pair named the cause: the sheet never said which tools the no-code track uses. The sheet was fixed, and the answer followed. So why not stop here?

  • Your code decided what to paste: everything, on every question. "What is an API?" pays for 38 rows too.
  • It only works while everything fits. One sheet does. The sheet, the practice sets and every lecture's notes do not.
  • Nothing shows which rows the answer used. There is no record to check.

Pasting works when you already know what the question needs. The model should be the one to say what it needs.

08Write the verifier first

Six questions, and what should happen for each, written from the sheet before the run. This is your Practice set 2 eval turned into code: the hard lines become checks a rule can run.

{{cut:06_verify.py|INVENTED = |def plain}} {{cut:06_verify.py|def plain|passed = 0}}

Three checks per case: did the system make the calls you wrote down, does the sentence say what it must, and does it avoid what it must not.

  • Our first version of the check failed two right answers. The model wrote "Google AI Studio" with a special space in it. plain() fixes the text before comparing. A rule check is code, and it has bugs too.
  • One run is not the result. The track question passed here. Run it again and it may not.

On the free Groq tier this takes a few minutes. The lines that say (rate limit, waiting…) are the code waiting for you. The free tier also has a daily limit of 200,000 tokens, and one run of the verifier uses about 8,000.

11A second app wants your tools

A friend wants to ask the same question inside the AI app they already chat with. Your cards and functions live inside tools.py. That app can't import your Python file. Copying the code into every app means fixing every bug in every copy.

So move the tools out of your app and put them at an address. That is an MCP server. On the Tool Bench the site ran one for you; with FastMCP you write it yourself:

{{cut:08_mcp_server.py|from typing import Annotated}}
  • The card is now the function itself. The docstring is the description. The type hints are the parameters.
  • The function body didn't change. It still calls tools.py.
  • Run it with python 08_mcp_server.py. The address is http://localhost:8000/mcp.

  • In Lecture 11's words: the second app is the host, the mcp() function is the client, and 08_mcp_server.py is the server.
  • An error comes back with isError: true and the same message your function raised. The track check still works from the other side.
  • Any MCP host can use the same address: an AI desktop app or a code editor that lets you add an MCP server. They send the same two messages.
  • The verifier still applies. Point it at cards and run_on_server and the same six cases run through the server.

13Do you need MCP?

Your situationUse
One app, your own code, a few toolsA function and a card, as in section 07. MCP adds a server to run and nothing else.
Two or more of your apps need the same toolsAn MCP server. One copy of the rule.
An app you didn't write should use your toolsAn MCP server. It is the only door that app has.
You want a tool someone else already builtTheir MCP server. You only write the client side.
  • MCP changes where the tool lives. It does not change the function, the card or the loop.
  • It does not make the answer right. Through the server, without the rule, the model skipped the tools in 3 runs of 4, the same as without MCP.
  • An address is a door. Anyone who can reach it can call the tool. Ours runs on your laptop only. Before it goes anywhere else it needs a key, like every server since Lecture 7.

Words from this lecture
Tool
A function your code runs when the model asks for it.
Card (tool schema)
The description of a tool that the model reads: name, description, parameters, required, types.
Tool call
The model's JSON naming a tool and its arguments. A request, not an action.
The loop
Model call, tool run, result back, repeated until the model answers or your code stops it.
Execution record
Tool, arguments, result and status for every call. The evidence.
Verifier
Cases written before the run: the calls that should happen, what the answer must say and what it must not.
MCP server
Tools at an address. It answers tools/list and tools/call for any app.
FastMCP
The Python library that turns a function, its docstring and its type hints into an MCP tool.

Keep this

Put the rule in a function. Describe the function on a card. Let the model ask and your code run. Write the cases before the run and believe only the record. When a second app needs the tool, give the tool an address.
