This page walks through the repo, one command at a time. Part 1 you do by hand. In Part 2 two agents and plain Python take over. The why behind each step is in the session notes.

The screenshots are real runs on the sample month, once in each harness. Your numbers will differ a little: a model never writes the same brief twice.

01Install

You need Python 3.10 or newer and git. Part 1 needs only a chat window. Part 2 needs one harness, logged in, and costs about $1.50 on the sample month with Claude Code.

curl -fsSL https://claude.ai/install.sh | bash
claude

The second line logs you in. You need a paid Claude plan or a Console account. On Windows PowerShell, install with irm https://claude.ai/install.ps1 | iex.

The loop uses sonnet to write briefs and opus to optimize. Put BRIEF_MODEL=haiku in front of a command to change one.

npm install -g @openai/codex
codex

Choose Sign in with ChatGPT (Plus or above), or use an API key.

The loop uses your Codex default model for both agents. Put BRIEF_MODEL=... OPT_MODEL=... in front of a command to change them.

curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.zshrc        # or ~/.bashrc
hermes model

Hermes comes with no model, so the last line picks one. The loop uses it for both agents. A small local model may not keep to the brief's format; the scorer will show you.

Our default was a local model, so for these runs we used Claude Sonnet. These lines apply to every command after them in that terminal:

export HERMES_PROVIDER=anthropic
export BRIEF_MODEL=claude-sonnet-5-5
export OPT_MODEL=claude-sonnet-5-5

Hermes has no fence while it runs: it can run any command. Run it on this repo and nothing else you care about.

02Get the repo

Clone it in your own terminal, not from inside the agent. Codex's sandbox has no network, so a clone from inside Codex fails.

git clone https://github.com/Siddhant-Goswami/harness-engineering-2
cd harness-engineering-2
python3 loop.py prepare

This is the sample month: 100 made-up links, products included, so every command works before you bring your own.

03Open your harness

Start it inside the folder (claudecodexhermes) and paste this:

Read the README. Run `python3 loop.py prepare` and show me the table.
Then walk me through Part 1, one step at a time. Wait for me after each step.
Do not label any link for me.

If Claude Code asks whether you trust the folder, pick Yes.

Carry on with the agent, or type the commands yourself. This page types them, so you can see each output.

Part 1 · by hand

04Get your saved links

Use links from 30 to 60 days ago. Yesterday's are no good yet: you cannot tell whether they helped. Give a tool that can use your browser this prompt:

Open my bookmarks on X. For every post I saved 30 to 60 days ago, write one row:
date saved, who posted it, the topic in one line, and the link.
Give me a CSV with the columns: date, source, title, url, label.
Leave the label column empty. Do not judge the posts.

05Label every link yourself

Fill the last column. No agent can do this step for you: it is your judgement going in.

Optional, and worth skipping the first time: your decisions that month in verifier/decisions.csv (date, question, outcome, how_it_turned_out, where the outcome is adopt, wait or ignore).

06A model labels them, blind

python3 loop.py blank

That writes manual/links-blank.csv: weeks 1 to 3 with the labels removed. Give it to any model with one line, and save the answer as manual/links-model.csv. From the terminal:

cat manual/links-blank.csv | claude -p "Fill the label column with signal or noise. Reply with the CSV only, header included, no code fences." > manual/links-model.csv
codex exec --skip-git-repo-check -o manual/links-model.csv "Fill the label column with signal or noise. Reply with the CSV only, header included, no code fences." < manual/links-blank.csv
hermes chat -Q -q "Fill the label column with signal or noise. Reply with the CSV only, header included, no code fences.

$(cat manual/links-blank.csv)" > manual/links-model.csv

Or attach the file in any chat window and send the same line.

07Compare

python3 loop.py compare manual/links-model.csv

Skip the percentage. Read the list for the mistake that repeats. Here it was Anvil and Quill DB: their posts sound urgent, but this reader uses neither tool.

08Write down the mistake, then one rule

The mistake goes in failures.md, with a tag:

## F1 · weeks 1 to 3
Saw: the model called four links signal: advisories and removals for Anvil and Quill DB.
Expected: urgent news about a tool I do not use is noise. I use Kiln, Orchard and Postgres with Vecstore.

One rule about that kind of link goes in harness/CLAUDE.md, with the same tag. A tagged rule can be reworded later, never deleted.

The reader uses Kiln, Orchard and Postgres with Vecstore. Urgent news about any other
tool (advisories, removals, "patch now") is noise to them, however loud the title. (F1)

git commit -am "F1: urgent news about tools I do not use is noise"

What just happened

You were the optimizer. Part 2 hands that job to a second agent, and leaves you the labels and the decision to keep a change.

Part 2 · the loop

09Run the first agent

Read harness/CLAUDE.md first. Then let the briefing agent write week 1:

python3 loop.py brief 1
RUNNER=codex python3 loop.py brief 1
RUNNER=hermes python3 loop.py brief 1

Run export RUNNER=codexhermes once and drop the prefix from every command after it.

Score it against your labels:

python3 verifier/score.py traces/try
(links found + 2 x decisions right - 0.5 x noise called important)
/ (links that mattered + 2 x decisions)

Here: (8 + 4 − 1.5) / 13 = 0.808.Here: (6 + 2 − 1) / 13 = 0.538.Here: (7 + 4 − 1.5) / 13 = 0.731. Noise costs half a point, or citing everything would win.

Now read what it did. The trace is every tool call and what came back:

python3 loop.py trace traces/try/week-1.jsonl

Look at the fetch.py line. The agent opened only some of the 25 links, the ones whose titles looked important. That habit is what the optimizer will go after.

10Record the baseline

The score of your setup before any agent changes it. Every round is measured against it.

python3 loop.py baseline
RUNNER=codex python3 loop.py baseline
RUNNER=hermes python3 loop.py baseline

Each week is written three times and the score is the mean. One brief is too small a sample: the same setup scored 0.46 and 0.89 on one week. Low to high shows the spread.

11Let the optimizer work

Read optimizer/CLAUDE.md once. Then run one round:

  1. ReportCode picks the worst week and lists every miss.
  2. ProposeThe optimizer reads the traces and makes one change in harness/.
  3. WallsCode checks it stayed in harness/ and kept every tagged rule.
  4. Brief againNine new briefs, scored the same way.
  5. Keep or revertKept only if the mean rose by 0.02 or more.
python3 loop.py round

The optimizer saw the habit from step 09 and added a rule: read every link. Then the agent cited nearly everything, and noise jumped from about 2 to 15. Worse, every week-1 run looked one folder up, so the wall scored them zero. Code reverted the change. That is the loop working.

RUNNER=codex python3 loop.py round

Codex's optimizer found a different habit: the agent read the right links, then left them out. One rule fixed it: 9 of 9 found every week.

RUNNER=hermes python3 loop.py round

The optimizer saw the habit from step 09 and added: read every link. All 9 links were found, but so were 14 noise links. The score fell, so code reverted it. The agent never decided that itself.

See what the optimizer read before it changed anything:

python3 loop.py trace traces/round-1/optimizer.jsonl

Then more rounds:

python3 loop.py run 2

In round 3 the optimizer spotted the pattern itself: every zero came from a run that looked one folder up. Its fix helped, but only by 0.009, under the 0.02 bar. Nothing was kept: the setup as shipped stayed the best.

RUNNER=codex python3 loop.py run 2

We stopped Codex after one round.

RUNNER=hermes python3 loop.py run 2

Round 2 learned from round 1. Not "read everything", but which links matter: changelogs, pricing and deprecations for tools the reader uses. 0.889, kept. Round 3 added measured results: 0.940, kept.

Every change and every revert is a commit, so git log --oneline is the history and python3 loop.py status the scores. Do not edit files while run is going: the walls will blame the optimizer and revert your edit.

12Open the hidden week

A rule that fits weeks 1 to 3 might only fit them. Week 4 has never been shown to either agent. It runs once.

python3 loop.py final

No change was kept, so both columns ran the same setup, and still scored 0.564 and 0.551. That gap is chance. Remember it when a round "wins" by a few hundredths.

RUNNER=codex python3 loop.py final

Week 4 rose too: 0.436 to 0.731. The rule captured how this reader decides, not something about weeks 1 to 3.

RUNNER=hermes python3 loop.py final

Week 4 rose, 0.577 to 0.731, but less than weeks 1 to 3. Part of the gain carried over; part only fit the weeks the loop could see.

Do not compare scores across harnesses. Each starts from its own baseline: compare its before and after.

For a longer run to read, the branch sample-run has four rounds: 0.739 to 0.991 on weeks 1 to 3, 0.666 to 0.949 on the hidden week.

git log origin/sample-run --oneline
git diff sample-baseline origin/sample-run -- harness

13When something goes wrong

"run thrown away, Bash reached outside harness/"

The briefing agent looked outside its folder, so the run scores zero. loop.py trace on that run shows the command. A few are normal; if every run does it, the next round's report shows the optimizer.

A round I expected to win was reverted

It has to beat the live score by 0.02. If low to high is wider than the gain, the gain may be luck. RUNS=5 in front gives a steadier number.

A change I made by hand was reverted

You edited a file while run was going. Stop, edit, commit, start again.

"Week four is already open"

final runs once, on purpose. To practise again, clone into a new folder.

Claude Code: "not logged in"

Run claude and log in again. The loop skips your own settings but uses your login.

Codex: the clone or a fetch fails

Clone in your own terminal (step 02). Inside the loop, agents.py turns network on for the briefing agent, so fetch.py works.

Hermes: it hangs or writes nothing

The model is usually not reachable. Start Ollama for a local model, or set a hosted one as in step 01. The first run in a clone also takes one to three minutes to set up.

14Bring your own month

  1. Replace verifier/links.csv with your labelled links. It needs no text column.
  2. Replace verifier/decisions.csv with your decisions, or leave only its header row.
  3. Delete harness/sources.md and harness/cache/.
  4. Run python3 loop.py prepare. Days 22 onward become week four.

Pages are fetched the first time the agent reads them, then kept, so a week reads the same on every run. Links behind a login (X, LinkedIn) come back as the title only.

Take home

Do Part 1 at least three times round. Then run 5 and final. Keep git log --oneline and both scores. Name one change you would never have written yourself, and one you would reject even though the score rose.
