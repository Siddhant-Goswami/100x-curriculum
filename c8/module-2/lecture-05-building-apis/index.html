Building APIs and backend

Your chat app still echoes. This week it sends a raw request to a model, and you prove the reply helps your user.

Python · requests · Gradio · GroqPost in the Discord code channel

The practical in one line

Four parts get you to any machine on the internet: an address, an action, a key and a package. A 200 proves the call worked. Only your verifier proves the reply helps.

01

Why the raw request

The cushion brokeThe SDK in Groq's quickstart worked until its default model returned a 404. The raw request is what you fall back on, and what lets you swap providers by changing one URL and one key.
A working answer still failedA reply that handed a business analyst a plan full of Python came back 200. The status code was right; the reply did not help.

02

Your path this week

  1. Send the raw request in the browser. The four parts to Groq, with your prompt and your user's real input. Predict the status code before every send; break it on purpose twice.
  2. Rip off the cushion in Python. Replace the echo in your Lecture 3 Gradio chat with requests.post. No SDK. The diff is the process and nothing else.
  3. Verify against your golden pair. One-line verdict, one prompt change, run it again.
  4. Submit six things on the Discord code channel. Track B (Aarav's workflow) is there if your Assignment 1 is not finished.
