APIs: Rip Off the Cushion

From an echo chat with no process to a raw POST request that plans Aarav's week.

Fri 9 Oct 2026Instructor: Siddhant GoswamiCohort 8 · Module 2

The one thing to keep

An LLM is not magic inside your app. It is a machine at an address, and you reach it like any API: an address, an action, a key and a package. The process is your prompt plus your user's input, sent to that address. None of it counts until your verifier says the output helps the person you built it for.

Read once end to end, then rebuild section 10 and section 13 on your own machine.

01Where We Left Off: A Chat That Repeats You

The Gradio app from the last code lecture: message is the input, the return line is the output, and there is nothing in between.

What you have to find is the process: the step that turns your user's input into an output they can use. You cannot write the process for a problem you have not done by hand.

02The Verifier Most People Skipped

A spec has three parts: the person, the golden dataset (ideal input and ideal output, written after talking to real users) and the verifier, a written condition that tells you whether an output is good. If you cannot tell a good output from a bad one in your user's domain, do not build yet.

Adding two numbers, an exam result and a refund decision gave three families: verification by rule, by judgment, and unverifiable. A system that gives the same output for the same input every time is deterministic, and this part of Module 2 lives there.

03Why Learn It When Agents Can Write It

Thinking can be outsourced. Understanding cannot.

We are not learning code to write it faster by hand. We are learning how deterministic systems behave, because a system you do not understand is a system you cannot verify: an agent, a mobile app or legacy enterprise software.

06Working Is Not the Same as Useful

Bhavani's code passed; the plan did not. It was full of code, and Aarav is a business analyst who cannot read Python yet. If the most complex technology on Earth does not deliver value to the end user, it was a waste of everyone's time.

07The Minimum Path

Under time pressure with one clear instruction, nobody changes the interface or adds ten parameters. Extra, unrequested structure is the fingerprint of pasting the task into an AI without understanding. Ask first: what is the smallest change that makes this work?

08Go to the Source, and Read the 404

Go to the official source before any AI. Groq's quickstart (pip install groq, export GROQ_API_KEY, a short script) failed as pasted:

Error 404

The model llama-3.3-70b-versatile does not exist or you do not have access to it.

404 is the client's mistake and means not found. Not found what? The message says: the model. Change the name to GPT OSS and run again. The status code tells you whose fault it is; the message tells you what.

09Free Is a Design Decision

Groq's free tier: 30 requests per minute, roughly 200,000 tokens and 1,000 requests a day. With a per-user quota, that powers a real MVP for one or two users at zero cost.

10Where Is the URL? Four Principles in the Code

Tested live in httpie.io/app (a browser address bar only sends GET). api.groq.com on its own failed: DNS finds a server, it does not tell the server what you want. The API reference gives the full endpoint:

POST https://api.groq.com/openai/v1/chat/completions

The whole Groq API, tested without writing code. You can do this in the browser right now.

11Prompt + Input = Package

The message content became a plain instruction followed by Aarav's real workflow:

"Here is the workflow of an analyst working at an IT company in India. Diagnose and generate a plan to automate this work, or a part of the work." [Aarav's workflow pasted below]

Both share one content field, but the instruction is yours and stays the same; the workflow is his and changes every time. The loop: chat UI captures input, prompt plus input goes to the LLM API, JSON comes back, you extract content, Gradio renders it to Aarav. Judge it against the golden pair, not "looks good".

12The Cushion: What a Library Hides

In the SDK code that worked, neither the URL nor POST is visible: both are hidden behind abstraction.

A passenger only needs a comfortable seat. A driver must understand the controls to operate the car.

Libraries and SDKs like Groq and Gradio offer comfort, but abstract away how things work.

When something breaks, the passenger is stuck. The driver knows where to look.

In software, that means understanding the source of truth: the endpoint, API key, request body, and response.

Convenience helps you move faster. Understanding gives you control.

15Any Machine, Four Lines

The raw version is provider-agnostic: swap the URL and key for OpenAI's and the same code runs. No new package, no dependence on anyone's SDK.

The four questions for any machine

What is the address? What is the action? Do I need a key, and how do I get it? What package does it expect? Answer those and about four lines connect your app to any machine on the internet.

17Words You Met

ProcessThe step that turns input into output: your prompt plus the user's message, sent to an LLM.
Golden datasetIdeal input and output pairs, written from doing the job by hand.
VerifierA written condition that says whether an output is good enough for the user.
Deterministic systemSame input, same output, every time. Verifiable by rule.
EndpointThe full address of one resource, path included. The domain alone is not enough.
DNSDomain Name System: finds which server a domain points to.
Status codeThe machine's verdict: 2xx worked, 4xx your mistake, 5xx theirs.
AbstractionHiding detail so you work at a higher level. Comfort that costs understanding.
SDKA provider's code wrapped around address, action, key and package.
Environment variableWhere keys live, outside your code, so they never reach a screenshot.
Rate limitRequests allowed per minute or day. Groq free: 30 per minute.
JQLJira Query Language, which the plan suggested for pulling Aarav's tickets.
