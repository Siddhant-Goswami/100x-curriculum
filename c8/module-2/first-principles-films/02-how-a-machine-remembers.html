How does a machine remember?

We built a machine that computes. Where does it write things down, and how does it find them again?

How to play: click the raised pieces in each drawing, or the buttons under it. Reach the goal and the explanation opens.

01The workbench forgets

Every memory does three jobs: write, store, read. Use the same gate as a trap: let electrons in and shut it behind them. Full is 1, empty is 0. Now you open a chat app and type hi.

What you just found

RAM is the workbench next to the processor: tiny buckets of charge, fast and leaky. Cut the power and it is wiped. Storage builds a wall around the charge (flash) or flips tiny magnets (disk). It holds on, and it is slow to write.

Same gate: used as a switch it computes, used as a trap it remembers.

02Slow down time

How slow is slow? Stretch the chip's clock until one tick takes one second. Adding two numbers now takes one second.

What you just found

That is why an app shows your message from the workbench straight away and saves it in the background. You never wait a year.

Principle OneFast memory forgets. Lasting memory lags.

03A card that says where things are

A disk does not know what a chat is. It offers one long row of numbered blocks and two commands: read(42) and write(90).

What you just found

That card is a file system: names on one side, block numbers on the other. It is the same trick as the letter A. The pattern 01000001 is 65, and 65 is A, only because we agreed. The bits don't know.

04Where does a link live?

One file holds everything and finds nothing. So split it. Each kind of thing (users, conversations, messages) is a table. Each fact about it is a column. Each thing is a row. That leaves the links between things.

What you just found

One number on the many side. A list on the conversation grows with every message, and the whole row is rewritten each time. With conv = 7 on each message, nothing grows. The list is never stored. It is found.

05One row in a billion

In 1970 Edgar Codd proposed: do not tell the machine how to search. Tell it what you want. That became SQL: SELECT text FROM messages WHERE conv = 7. But how does the machine find those rows without reading every one?

What you just found

The sorted copy is an index. Put signposts above it, each pointing to a thousand more, and you have a B-tree: one hop reaches a thousand rows, two a million, three a billion.

The price: every write now happens twice, once in the table and once in the index.

Principle ThreeFaster reading means a second copy.

06In your build

  • Things, facts and links are what you modelled in Lecture 6. The number on the many side is the pointer.
  • Your tables from Lecture 7 are lasting memory. What your page shows before the save returns is the workbench.

07Check yourself

Answer in your head, then open it.

RAM does two of the three jobs well. Which one does it fail?

Store. The buckets leak, and with no power nobody tops them up.

Why does a chat app show your message before it is saved?

The workbench is fast and storage is slow, so it shows from the bench and saves in the background.

Name three places where a little data says how to read the rest.

65 means A, the directory of block numbers, and the column names at the top of a table.

What do you pay for an index?

A second structure to keep, and every write happens twice.

Words you now own
RAM
The workbench next to the processor. Fast, wiped when the power goes.
Storage
Flash or disk. Holds on without power, slow to write.
File system
A directory of names and block numbers that says how to read the disk.
Table, column, row
A kind of thing, a fact about it, one thing.
SQL
A language for saying what you want, not how to find it.
Index
A sorted second copy of one column, with signposts, for fast lookup.
