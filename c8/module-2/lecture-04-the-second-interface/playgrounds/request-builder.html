01Echo: the face with no brain

This is your Lecture 3 UI. Type anything. It hands your words straight back, because the process is an echo. Where would the brain go, and how would this page reach it?

The brain lives on another machine. To reach it, this page has to send a message that the other machine can read. The rest of this page is that message.

03GET: read, and watch the space

httpbin.org is a public echo machine: it sends back whatever it receives. Type a word, then a sentence with a space. Watch the address before you press Send. What happens to the space, and why?

An address cannot hold a space, so it is translated to %20. This page and your browser do that for you. Your code and your no-code tools will not always do it, and a request with a raw space in the address is a classic 400.

04POST: send a package

Same echo machine, a different door and a different action. This time you send a package: Aarav's Friday workflow, in JSON. Press Send, check for a 200, then find your text inside the reply.

Look at the raw request: the package needs a header that says which format it is in, Content-Type: application/json. Without it the machine has to guess, and machines do not guess.

05Groq: a model behind a deterministic door

Now the brain. Groq runs open-weight models on its own chips. You reach its model with the same four parts. Groq with a q, not Grok.

  1. Get a free key. Open console.groq.com/keys, sign in with Google or GitHub, click Create API Key, name it c8-lecture04, and copy it. Groq shows it once.
  2. Paste it below. The model list loads from Groq itself. That load is a GET with your key: your first keyed request. Keep openai/gpt-oss-120b.
  3. Press Send. Hands up for a 200. Then press Send the same request again and compare the two answers.

Your key stays in this tab's memory. It is not saved, and it is gone when you reload. Free tier: 30 requests a minute, counted per Groq account, not per key.

The door is deterministic. What comes through it is probabilistic.

Same address, same action, same key, same package, different words. Two answers to the same request: which one is right, and who decides?

Find your own key

Open DevTools (right click, Inspect), go to Network, click the chat/completions request, then Request Headers. Your key is there in plain text. That is fine on your private tool. If Aarav's product worked like this, every visitor could read his key and spend his money. So where should the key live? Keys, and the box they live in.

The machine from Round Three is real. It lives at https://100x-curriculum.vercel.app/aarav and checks the parts in the order you learned them: address, action, key, package. It issues its own keys.
