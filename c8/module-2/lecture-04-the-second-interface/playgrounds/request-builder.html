02Read: your first request

A Read fetches something that already exists. httpbin.org is a public echo machine: it sends back whatever it receives, so you can see exactly what you sent.

  1. Look at the four bands. Address is filled in for you. Action is Read · GET. Key: none needed. Package: none, because a Read sends no package.
  2. Press Send. You should see a large 200, and under The part you want, your text.
  3. Type a sentence with a space in the text box, like hello world, and watch the address. The space turns into %20 before anything is sent. An address cannot hold a space, so it is translated. Your code and your tools will not always do this for you; a raw space in an address is a classic 400.
  4. Click Show the raw request. This is the request as text: the action, the address, and nothing else.

03Create: send a package

Same echo machine, a different door, a different action. This time you send something: Aarav's Friday workflow, as JSON.

  1. Check the package band. It holds {"text": "…"} and says ✓ valid JSON. Try deleting a quote: it turns red. Put it back.
  2. Press Send. Look for 200, then find your text at json.text in the reply.
  3. Click Show the raw request. A package needs one more header, Content-Type: application/json, so the machine knows which format to read. Machines do not guess.
Code track · the same request in Python

04Round Three, for real

The machine from Round Three is real. It lives at https://100x-curriculum.vercel.app/aarav and checks the parts in the order you learned them: address, action, key, package. It needs a key, and it issues its own.

Part A · Create a key

  1. Replace your name in the package with your name.
  2. Press Send. Expect 201: something new was created, your key. It is copied into Part B's key box for you.

Part B · Create a diagnosis

  1. Check the key band holds your aarav_… key. Press Show to check it pasted fully.
  2. Press Send. Expect 201 and a diagnosis of Aarav's Friday report.
  3. Press Send the same request again. The two replies sit side by side. They are identical: this machine follows rules. Remember that for step 8.
  4. For the practice set: take a screenshot of the reply. The reply shows only the start of your key.

05Break it on purpose

Every failed request comes back with a code, and the code points at one part. Learn the codes by causing them, one part at a time.

  1. Pick a button below. It changes one part of the Part B request above.
  2. Before you press Send, write down the code you expect.
  3. Press Send in Part B. The red box names the part and what to change.
  4. Press Put it right, then try the next button. Fill in the practice set table as you go: what you changed, the code you got, the part it points to.
CodeMeansWhose fault

06Whose fault? Every code

Each card sends one real request. Before you press Send, pick whose fault the reply will be. 2xx worked. 4xx you sent something wrong. 5xx their machine broke.

07Read real traffic

Every request you sent here is visible in your browser's own tools. Real products work the same way. Reading this is how you check what an app actually sends.

  1. Open DevTools. Mac: Cmd Option I. Windows: F12 or Ctrl Shift I. Or right click anywhere, Inspect.
  2. Click the Network tab, then the Fetch/XHR filter. Click the clear button (a circle with a line).
  3. Scroll up to step 4, Part B, and press Send. A row named diagnoses appears.
  4. Click it and find each part:
    AddressHeaders → Request URL
    ActionHeaders → Request Method
    KeyRequest Headers → authorization
    PackagePayload (what you sent) and Response (what came back)
    CodeHeaders → Status Code
  5. Optional, a real product: do the same on ChatGPT. Reading the Network tab walks through it, including the one header you must never expand or paste.

08Put a model behind it

Aarav's UI has a face. It needs a brain: a model that reads his workflow and writes a plan. Groq runs open-weight models on its own chips, and you reach them with the same four parts. That is Groq with a q, not Grok.

Part A · Get a free Groq key (one time, about 3 minutes)

  1. Open console.groq.com/keys in a new tab. It is a website, not a download.
  2. Sign in with Google. No card needed.
  3. Click Create API Key, name it c8-lecture04, and click Submit.
  4. Copy the key now. Groq shows it once. Do not paste it anywhere except the box below.

Part B · Send your first request to a model

  1. Paste the key into the key band. Wait a second: the model list loads from Groq itself. That load was a Read with your key, your first keyed request. If it says 401, the key was not copied fully.
  2. Keep the model openai/gpt-oss-120b and the message as it is.
  3. Press Send. Expect 200. The answer is at choices[0].message.content. The reply also carries a reasoning field, the model's scratchpad. Ignore it.
  4. Press Send the same request again. Same address, action, key and package. Different words. Compare that with Aarav's service in step 4.

Your key stays in this tab's memory. It is not saved and is gone when you reload. Free tier: 30 requests a minute, counted per Groq account, so use your own account, not a friend's key.

The door is deterministic. What comes through it is probabilistic.

Two answers to the same request. Which one is right, and who decides? Write one line on which you would trust, and why. That line is the start of a verifier.
