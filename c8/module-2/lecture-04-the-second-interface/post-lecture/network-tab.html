Reading the Network Tab

Every request your browser sends is written down. Open the list, click one, and find the four parts of the request and the two parts of the reply.

Sat 3 Oct 2026Cohort 8 · Module 2Chrome

What you are looking for

Every request carries an address, an action, a key and a package. Every reply carries a code and a package. The Network tab shows all six. In Lecture 2 you were told you did not need to read it yet. Now you do.

01Open It

Your machine
  1. Open DevTools. Right click anywhere on the page, then Inspect. Or the shortcut: F12 or Ctrl+Shift+ICmd+Option+I.
  2. Click the Network tab. If you cannot see it, click » at the top of DevTools.
  3. Filter to Fetch/XHR. These are the requests a page sends by itself, after it has loaded. Images, fonts and styles drop out of the list.
  4. Clear the list. The circle with a line through it, top left. Now the next request you cause is the only one there.
  5. Cause one request, then click it. The right side shows tabs: Headers, Payload, Preview, Response. The six parts live across those tabs.

The panels below are drawn in HTML so they read the same on every machine. Real screenshots will be added to this page from assets/images/.

02Part 1: ChatGPT's Real Request

Log in to ChatGPT in Chrome, open the Network tab, filter to Fetch/XHR, clear it, and send "hi". Several requests appear. One fires just before the message and carries a name like chat-requirements: the site checking you before it lets the message through. The one you want is named conversation. In recent builds its address ends in /backend-api/f/conversation. The exact name changes from time to time; look for the one sent at the moment you pressed Enter.

If you are logged out, ChatGPT uses different addresses. Log in first.

Find each part

PartWhere in the Network tabWhat you see
addressHeaders → Request URLThe machine and the door: chatgpt.com and /backend-api/…/conversation
actionHeaders → Request MethodGuess first: Read or Create? Then look. The answer is in the lecture notes.

packagePayloadJSON. Find your "hi" inside it, next to the model name and an id for the conversation.

Two things you never expand, copy or paste

The authorization header and the cookie header. Together they are your login. Anyone holding them is you, until they expire. Not into Discord, not into a screenshot, not into an AI chat asking it to "explain this request".

The reply arrives in pieces

Click Response, or EventStream if Chrome shows it. The content type of this reply is text/event-stream. The machine does not send one package at the end. It sends many small ones as the model writes, and the page adds each one to the screen. That is why ChatGPT's words appear one by one.

data: {"message": {"content": {"parts": ["Hi"]}}} data: {"message": {"content": {"parts": ["Hi!"]}}} data: {"message": {"content": {"parts": ["Hi! How can"]}}} data: {"message": {"content": {"parts": ["Hi! How can I help?"]}}} data: [DONE]

Simplified. The real stream carries more fields; the shape is the same.

The question this page exists to ask

The Builder is your private tool, so this is fine here. If Aarav's product were built the same way, every visitor could open this tab, copy his key, and spend his money. Where should the key live instead? Answer it before you read Keys.

04Part 3: The Space That Became %20

Open exercise 3, or paste https://httpbin.org/get?text=hello into Chrome's address bar. Then change hello to hello world. Edit the existing address; if you retype it from scratch, Chrome may run a Google search instead.

All1 request
get?text=hello%20world200
HeadersResponse

Request URLhttps://httpbin.org/get?text=hello%20worldaddress

Request MethodGETaction · Read

Status Code200 OKcode

An address cannot hold a space, so the browser translated it to %20 before sending. Look at the Request URL here, not the reply: httpbin decodes the text back to hello world in its answer. Your code and your no-code tools will not always do this translation for you. When they do not, the machine replies 400.
