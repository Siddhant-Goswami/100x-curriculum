Card 1 · The envelope

Every request carries four things. Every reply carries two.

Address100x-curriculum.vercel.app/aarav/diagnoses
ActionCREATE · spelled POST
KeyAuthorization: Bearer ••••••••
Package{"workflow": "I open Jira, read the week's tickets, write a status report and post it on Slack. About 90 minutes."}

The reply

Code201 Created
Package{"diagnosis": {"repeated_pattern": "a weekly status report", "bottleneck": "reading every ticket", "first_ai_step": "draft from a Jira export"}}

Address = URL · Action = method · Key = a header · Package = the JSON body · Code = status code

Card 2 · Status codes

Read the first digit. It tells you whose fault it is.

CodeMeansPart to checkWhose fault
200Worked—Nobody
201Worked, something new was created—Nobody
400Package unreadable, or a part is missingpackageYours
401Key missing or wrongkeyYours
404Nothing at that addressaddressYours
405That door does not take that actionactionYours
429Too many requestsslow downYours
500Their machine broke—Theirs
2xx worked · 4xx you sent something wrong, because the machine does not guess · 5xx their machine failed

A 200 means your request was understood, not that you got what you wanted.

Card 3 · CRUD and HTTP methods

Four actions. The method is how each is spelled on the wire.

CRUDMethodAarav's example
ReadGETOpens his past diagnoses · GET /diagnoses
CreatePOSTSubmits his Friday workflow · POST /workflows
UpdatePATCH"weekly" becomes "every Friday" · PATCH /workflows/7
UpdatePUTResends the whole workflow · PUT /workflows/7
DeleteDELETERemoves an old workflow · DELETE /workflows/7
CreatePOSTAsks ChatGPT about the weather: a new reply is created
Read what already exists: GET, nothing changes. Create something new: POST. Update it: PUT (all of it) or PATCH (part of it). Delete it: DELETE.

Companies do not always follow the convention. For any app, the Network tab is the truth.

Card 4 · The ladder

Six problems. Each fix became a part of your request.

1Morse, 1844A wire is on or off → a shared codebooklanguage
2ASCII, 1963No human operator → a number per character · the characters in your packagelanguage
3TCP/IP, 1974–83Many machines, lost packets → address + confirmed deliveryprotocol
4HTTP, 1989–91What do you want? → action key code · HTTPS seals itprotocol
5REST, 2000Fifty vocabularies → nouns as addresses, CRUD as verbsprotocol
6JSON, 2001Python and JavaScript must agree → the packagelanguage
An interface = a common language + a protocol. Every rung is Input → Process → Output.

Card 5 · The Groq request

A model behind the same four parts.

Addresshttps://api.groq.com/openai/v1/chat/completions
ActionPOST · Create: a new reply
KeyAuthorization: Bearer <your gsk_ key>
PackageContent-Type: application/json
{"model": "openai/gpt-oss-120b", "messages": [{"role": "user", "content": "…"}]}
Reply200 · text at choices[0].message.content (ignore "reasoning")

Free tier. 30 requests a minute, 1,000 a day on gpt-oss-120b. Limits are per account, not per key. Fallback model: openai/gpt-oss-20b.

The door is deterministic. What comes through it is probabilistic. Same request twice, different words. Who decides which is right?

Card 6 · Key rules

A key is a password a machine can use. Treat it like one.

  1. A key goes in a header, never in the address. Anyone can see an address.
  2. Never paste a key in Discord, a screenshot, a help post or an AI chat. Mask it: gsk_••••.
  3. A key in a web page's code ships to every visitor. Real keys live in the backend.
  4. If a key leaks, revoke it and make a new one. Do not wait to find out.
  5. Your ChatGPT authorization header is your login. Never expand it on a shared screen.
