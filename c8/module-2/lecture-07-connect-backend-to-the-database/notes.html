Lecture notes · Lecture 7

A database is a machine at an address

Pointers, not prose. The nine steps, the three games, what you predict, what you stamp, and what you post.

Fri 16 Oct 2026Instructor: Siddhant GoswamiCohort 8 · Module 2

01The lecture in one line

  • Principle: a database is a machine at an address. SQL is its package.
  • Done equals: a classmate opens your vercel.app URL, gets a plan, refreshes, and the plan is still there. They search the Network tab and find no key.
  • From Lecture 6: storage was a file on your server, and the tables were drawn on paper. Today the file dies and the paper tables get typed. See it drawn: the lecture on a whiteboard.

03Three games, all 120 minutes

You play the parts the lecture is about: the attacker who finds the key, the many writers who lose data, and the verifier who checks someone else's work.

  • 🎯 Predict the status. Before every run, post your guess in chat. A right guess is 1 point. The answer key is in section 08, so guess first.
  • 🎮 The debt card. Three debts. Stamp each one when your own deploy passes, and post every stamp with a screenshot. A partner's "verified" closes the card.
  • 🎮 Roll call stampede. Twice in the lecture, the whole room POSTs its name to the live URL. The route skips Groq on purpose: sixty students on /api/diagnose would hit Groq's limit and fail for the wrong reason.

04Part 1 · Pay the key debt (0 to 30)

  • 01 The leak. A key pasted into a page. Inspect, Network, Send, read the Authorization header aloud. Whose machine? Whose key? Who else can read it? 🎯 is the key visible?
  • 🎮 Key hunt. The leak page goes live with a throwaway key. First to post the key's last 4 characters wins. The key is revoked on screen right after.
  • 02 Strip it to the function. diagnose(workflow) returns a plan, from the terminal. The UI was never the process.
  • 🎮 Dial cards. The room fills in the four dials for your API in chat before any FastAPI code is typed.
  • 03 The function on your server. A FastAPI route on Vercel, the Groq key in an environment variable. 🎯 what does the first live call return?
  • 🎮 Stamp time, 10 minutes. Split your own Lecture 5 app the same way and post a /docs screenshot. A clean Network tab stamps 🔑.
  • 04 Gradio becomes a client. One URL in the file, no key. The key lives on the machine that spends the money. Debt left: this UI runs on your laptop only.

05Part 2 · The file dies (30 to 50)

  • 05 memory.txt. Each request reads the file, asks Groq, writes the file back with one more line. GET /api/plans returns every line. Locally it works. 🎯 what will a POST to the live URL return?
  • 🎮 Stampede 1. Everyone runs the roll call against the live URL. Every single student gets a 500: read-only file system. A Vercel function has no disk you own, and the machine is thrown away after each request.
  • Two writers. Two volunteers, two terminals, one count of three, against the local server. 🎯 how many plans did the file keep? Both read the same old file. The one that writes last wins.
  • What broke, three things. The data must survive the server being thrown away. Many writers must save without losing anything. "Every plan for workflow 1, oldest first" must be answered without reading everything.
  • The move. Size moved the LLM off your server. Survival moves storage. The data goes to a machine built for it, reached by API.

06Part 3 · Another machine (50 to 85)

  • Supabase project. Settings, then API: one URL, two keys.
  • 🎮 Dial cards again. The room fills in Supabase's four dials before any code. 🎯 what will the first POST return?
  • Call it before it has a shape. The httpie POST fails: relation "diagnoses" does not exist. The machine needs a shape. Lecture 6 said it first: you cannot store what you cannot describe.
  • 🎮 Shape the table. The room calls out the columns from the Lecture 6 model. Only what is called out gets typed. Then check against schema.sql and run it in the SQL editor.
  • 06 SQL is the package language. create table is a thing becoming a table. Each line is a fact becoming a column. primary key is the row's address. references is the pointer on the many side. default now() is the memory.txt timestamp. The last line is Aarav's Lecture 6 question, as SQL. 🎯 what does the same POST return now?
  • Two keys. anon / publishable is for machines you don't control, like a browser (Lecture 9). service_role / secret bypasses every lock: server environment variables only. Leave Row Level Security alone today (Lecture 8).
  • 07 The cushion. The SDK makes the same two calls.
  • 🎮 What does it hide? Each student names one thing the SDK hides. Repeats don't count. (The URL, the headers, apikey, the JSON…)

07Part 4 · Strip the cushion, ship it all (85 to 120)

  • 08 The server remembers. The file append becomes an insert. The Lecture 6 question becomes a route: GET /api/workflows/1/diagnoses. Add the Supabase URL and secret key as environment variables and deploy. Gradio from step 04 still works, unchanged.
  • The lie. workflow_id: 1 is hardcoded on purpose. Lecture 8 opens on it.
  • 🎮 Stampede 2. The same roll call, now to the step 08 URL, with the roll table on the projector. Sixty writers, sixty rows, on a machine nobody in the room owns. Requirement 2, done by the room.
  • 09 Rip off Gradio. All it was hiding: a text box, a button, one POST. fetch is requests.post in the browser. The page sits in the same Vercel project as the API, so same origin and no CORS. 🎯 how many keys in the Network tab?
  • The HLD. Aarav's browser runs plain HTML. Your Vercel function exists only while it answers. Groq thinks. Supabase remembers.
  • Proof, in debt order. 1. Type on the live page, then GET the list: one row. 2. Refresh: still one row, 🔄 paid. 3. Change a comment, redeploy, GET again: still one row, 🚀 paid. 4. Network tab: only your URL, no key, 🔑 paid. 5. Swap and verify.
  • 🎮 Swap and verify. Swap URLs with a partner. They get a plan, refresh, search for a key, and post "verified" with your URL. Nobody verifies their own. That post stamps 🔄 and 🚀 and closes the debt card.
  • Hook for Lecture 8. Your partner just read Aarav's plans without a password. Whose row is this?

09Practice set

  1. Split: a FastAPI route on Vercel, and Gradio running locally with one URL and no key.
  2. Type your model: every table from your Modelling Lab board, with references on every _id.
  3. Two verbs: one insert route, and one select route that uses where and order by.
  4. Strip Gradio: public/index.html with one fetch, in the same Vercel project.
  5. Get verified: a classmate posts "verified" with your URL.
  • httpie before the SDK.
  • No key in HTML, in screenshots, or in any file you share. Keys go in environment variables.
  • Ask an LLM to explain errors, not to write your create table.

10Flags

  • Vercel: the file system is read-only except /tmp. A cold start takes about a second. If / hits the function instead of public/index.html, add a rewrite in vercel.json.
  • Supabase: free projects pause after 7 idle days. The supabase package is pinned in requirements.txt.
  • Groq: the free tier allows 30 requests a minute. Check the model name on the day.
Words from this lecture
cold start
The first request after a function has been idle. The machine is built before it answers, so it is slow once.
read-only file system
A disk you can read but not write. A Vercel function's disk, apart from /tmp.
relation
Postgres's word for a table. "Relation does not exist" means no table by that name.
service_role key
The secret key that bypasses every lock. Server environment variables only.
anon key
The publishable key for machines you don't control. Waits for Lecture 9.
Row Level Security
Rules on who may read or write which rows. Off today. Lecture 8.
same origin
Page and API served from one address. Then the browser never asks the CORS question.
the cushion
An SDK: the same call with the address and headers hidden inside a client object.

Keep this

Four machines, four jobs. Aarav's browser shows. Your Vercel function answers, then disappears. Groq thinks. Supabase remembers. Every arrow between them is the same four dials, and the only machine that ever holds a key is yours. Done is not a screenshot. Done is a classmate's "verified" next to your URL.
