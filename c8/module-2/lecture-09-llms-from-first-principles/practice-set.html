Verify your own job

One real working week. Every atomic task. A verifier, or the reason there isn't one.

Follows Lecture 9, Fri 30 Oct 2026.

The brief

List every atomic task from one real working week, write how each task's output is verified, and mark which of them already have the data a machine would need to learn them. Across 100x alumni, about 80% of tasks were verifiable. This sheet tells you your number.

01Why this exists

  • Aarav was a proxy. In the lecture his three Monday tasks all passed. The skill is drawing the line between rule and judgment on work you are actually paid for. Notes, section 10.
  • It is the input to the next four weeks. You will pick one task from this sheet, gather its data, and end the module evaluating a model on it. A vague sheet means a vague model.
  • A verifier is not automation next quarter. How soon depends on how much data it takes, usually more than you think.
  • A rule-verifiable task may not need an LLM at all. Start left of the line.

02Track A: your own job 0 of 7 ready

Preferred. If you have any paid work at all, freelance included, use this track.

03Track B: the job you want 0 of 3 ready

Not working right now? Reconstruct a week from evidence. It is the weaker version on purpose: you are verifying someone else's week.

04Rules

  • Predict before you count. The gap between guess and count is part of the result.
  • Your week, not a generic one. Do not ask an LLM to list the tasks of your role. A list inferred from a job title is the average job, and the average job is exactly what a lab can already buy data for. An LLM may help you phrase a verifier or give a second opinion on a bucket.
  • "It's subjective" is not a verifier. Every judgment row names a judge and a signal. If you cannot name either, the row is unverifiable for now, and you say why.
  • Start deterministic. For every Automate row, note whether it needs an LLM at all, or whether a script, formula or template would do.
  • Model work stays locked. No training, fine-tuning or agent building on these tasks until the sheet is in. To experiment on the side, use a local open-source model (Qwen 3.5 on Ollama).

06When you are stuck

Not sure whether a task is verifiable? Write the best verifier you can and flag the row. Never leave it blank. A flagged row is a good question for the next live session or office hour.

For a second opinion on a bucket, paste your own tasks into the delegation framework. It sorts what you give it; it does not write your list.

07After you submit

Your candidate task becomes the task the rest of this module is built around: data first, then a model, then an evaluation of that model on your own job. A sharp verifier and a real data source get you to the evaluation. "Help the team" gets you four weeks of rewriting this sheet.

Find your own number before someone else does.
