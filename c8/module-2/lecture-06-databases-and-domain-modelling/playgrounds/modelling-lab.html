Aarav picks a tone for each plan. Today, tone is a fact on the plan. What would have to change in the product for tone to become a thing with its own block?

Reveal

If users could save named tones and reuse them across plans, a tone would be created, read, updated and deleted on its own. It would pass the question 1 test, so it would become a thing. The word does not decide. What the product needs to do with it decides. That is the whole skill: drawing the line between a thing and a fact, for this app.

03Question 3: how do they connect?

thingsfactslinks

Your blocks now hold facts, but they do not know about each other. Look at the messages: which conversation is each one in? Nothing on the row says. To connect two blocks, a row in one must be able to point at a row in the other.

First, give every row an address. To point at a row you need a way to name it, and its words cannot do it: two messages both say "okay". So number the rows. That number is the row's id, also called its key. It never repeats.

Then put a pointer on one side. A pointer is a column that holds another row's id. Which side gets it? Try conversations: conversation 7 has three messages, and a column holds one value per row. Try messages: each message is in exactly one conversation, so one value is enough. The pointer goes on the side that has only one to point at. Name it after the other block, singular, plus _id.

So every link comes down to two questions, asked both ways. The two answers give the link its shape, and the shape says where the pointer goes.

Now link Aarav's blocks. For each pair, answer both questions, then place the pointer. Each card draws the link as you go.

04Rows or files?

thingsfactslinksfiles

Pause and think

Aarav attaches a screenshot of his Jira board. Can it go in a column?

Reveal

No. A column holds a value you can type: text, a number, a date, yes or no. A screenshot is bytes. It goes in file storage, and a row keeps the link to it, plus the facts about it: which message it came with, its name, when it arrived. Rows for facts, files for everything large or binary, and a pointer between them.
