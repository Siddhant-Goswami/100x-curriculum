When a check is a cross

Every cross in the lab names a table or a column. Read it, fix that one thing, check again.

01The Crosses You Should Expect

No table for …
Cause

The brief names a thing you have not given a table, or your table's name is too far from it (the checker accepts singular, plural and common synonyms).

Fix

Add the table, or rename yours to the noun the brief uses.

… has no key
Cause

No column is marked key. Every row needs an address so other rows can point at it.

Fix

Add an id column and tick key. The builder does this for every new table; you removed it.

… has no pointer to …
Cause

The link exists in the brief but not in your tables. The many side needs a column holding the other table's key.

Fix

On the many side, add a column named the other table singular plus _id, tick points to, and pick the table.

… is a pointer but does not point to …
Cause

You ticked points to but left the dropdown on "which table?", or picked the wrong one.

Fix

Open the dropdown under the column and pick the table the brief names. If it is not in the list, that table has no name yet.

… should be a pointer to …
Cause

The column is there, with the right name, but it is a plain column. A name alone does not make a link.

Fix

Tick points to on it and pick the table.

… points the wrong way
Cause

The one side carries a pointer to its many side: a pet_id on owners. One cell cannot hold many pets.

Fix

Remove that column. The many side already carries the link.

Link missing: …
Cause

The table is there but has no pointer to the other side.

Fix

Same as "has no pointer to": add the column on the many side, tick points to, pick the table.

… must be marked unique
Cause

The brief says exactly one row per parent (one summary per post). A plain pointer allows many.

Fix

Tick unique on the pointer column. A second row for the same parent is then refused.

… is missing …, and that is the point of this brief
Cause

The one column the brief is about (quantity, grade, start date, status) is not on the table where it belongs.

Fix

Re-read the brief's last line. The column describes exactly that row, usually the pairing row.

Two tables share the name … / … has two columns called …
Fix

Rename or remove the duplicate. Pointers cannot tell twins apart.

… is a pointer with no table to point at
Cause

The dropdown is still on "which table?", or the table it pointed at was deleted or renamed.

Fix

Pick the table again.

… could use a … column
Cause

A suggestion, shown with a dot. It never blocks done.

Fix

Add it if the brief's product would need it. Otherwise ignore.

02The Lab Itself

My progress disappeared
Cause

The lab saves in this browser on this device. A private window, another browser, cleared site data or another device starts empty.

Fix

Use the same browser. Take your screenshots as you go.

The reveal will not open
Fix

Write at least a few words in the box above it. It opens as soon as there is an answer.

Section 5 shows dashed boxes
Cause

Section 5 only draws what you placed. A dashed table or column is one you have not tagged, placed or linked yet.

Fix

Click "place it" on the dashed piece; it takes you to the section that places it.

What do I do with the downloaded sheets?

One CSV per table, with two sample rows. Open them in Google Sheets or Excel to see your model as sheets. Next week the no-code track can import them into Supabase as a starting point.

I want to start over

"Start again" on a builder resets only that brief. "Reset the whole lab" at the bottom of section 7 wipes everything on this device, including checkpoints.
