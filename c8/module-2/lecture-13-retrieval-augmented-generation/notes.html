Find the right few paragraphs.

Two questions about our own notes, and how to find each answer.

The LLM has never read our course notes. So we ask it questions about our own course, and check each answer with a simple rule. So far we have done two:

The questionWhat it gives you to search with
Q1What is Lecture 6 about?A number: the lecture number
Q2Which lecture teaches Verifier's Law?Exact words

What the question gives you decides how you find the answer.

01Look it up by its number

First, ask with nothing attached. The LLM gets it wrong. For Q1 it asked which course we meant. For Q2 it named a lecture at MIT. It sounded just as sure when it was wrong.

It has never seen our notes. You can give them to it in two ways:

  • Paste the notes into the prompt.
  • Give the LLM a tool that fetches a page. You did this in Lecture 12.

Q1 has a number in it: Lecture 6. So a tool can fetch Lecture 6 by its number. The LLM reads it and answers: databases and domain modelling. Q1 passes.

The tool fetches the page, the page is added to the prompt, and the LLM writes the answer. Fetch is retrieval. Add to the prompt is augmented. Write is generation. Together: retrieval-augmented generation, or RAG.

You already built RAG in Lecture 12. Next: what if the question has no number in it?

02Why not paste it all?

All twelve notes pages add up to about 30,000 tokens. The LLM can read about 131,000 at once, so they fit. For a small pile like ours, pasting is fine. Anthropic's own guidance says: under about 200,000 tokens, just put it in the prompt.

So why not always paste? It has three costs.

  • You pay every time. Each question sends all 30,000 tokens again, just to use two paragraphs. At $0.15 per million input tokens, 1,000 questions a day for 30 days costs $135. Send only the two passages that matter, about 1,500 tokens, and it costs $6.75.
  • No source. The answer does not say which page it came from, so you cannot check it (Lecture 11).
  • Longer prompt, worse answers. Answers get less reliable as the prompt grows, even before it is full. Chroma tested 18 LLMs in July 2025, and all of them did this.

On a free Groq key, you hit a fourth problem first. The free limit is 8,000 tokens a minute. Pasting everything asks for 31,131, so Groq rejects the request before the LLM reads a word.

Rule zero: if it fits, the questions are few, and nobody needs the source, just paste it.

Interviewers ask this first, and most people skip it. When pasting is not enough, the job changes. Do not give the LLM everything. Give it the right few paragraphs. How do you find them?

03Find it by its words

Q2: "Which lecture teaches Verifier's Law?" No number this time. But it has exact words.

Press Ctrl+F across all the passages and type Verifier: 24 passages light up, in 6 lectures. Too many to hand over. Type the full name, Verifier's Law: only 2 passages are left, both in Lecture 1. Hand those two to the LLM. Q2 passes.

Ctrl+F reads every passage, every time. Fine for twelve pages. Far too slow for twelve million. Books solved this long ago with the index at the back: each word, and the pages it appears on. You build it once, and then every search is a quick lookup (course lesson 2.6). Searching this way is called keyword search.

Q1 gave us a number, so we looked it up. Q2 gave us exact words, so we searched for them.

Keep this

If everything fits and the questions are few, paste it. If not, find the few passages that matter. A number in the question? Look it up. Exact words? Search for them.

04Now do the Retrieval Bench

Run Q1 and Q2 yourself, one step at a time: ask with nothing attached, fetch by number, paste it all, then search by words. Those are the first four stations. Bring the Groq key you used on the Tool Bench, or make a new one at console.groq.com/keys.
