Tutorial · Harness Engineering 2.0 · Claude Code, Codex or Hermes

Run the loop yourself.

Every command in the repo, by hand and then with the loop, in Claude Code, Codex or Hermes.

This page walks through the repo, one command at a time. Part 1 you do by hand. In Part 2 two agents and plain Python take over. The why behind each step is in the session notes.

The screenshots are real runs on the sample month, once in each harness, with the repo as it was on 23 November 2026. Your numbers will differ a little: a model never writes the same brief twice.

01Install

You need Python 3.10 or newer and git. Part 1 needs only a chat window. Part 2 needs one harness, logged in. With Claude Code it costs about $1.50 on the sample month, and about $7 on a real month of 100 or so X posts.

terminal
curl -fsSL https://claude.ai/install.sh | bash
claude

The second line logs you in. You need a paid Claude plan or a Console account. On Windows PowerShell, install with irm https://claude.ai/install.ps1 | iex.

The loop uses sonnet to write briefs and opus to optimize. Put BRIEF_MODEL=haiku in front of a command to change one.

terminal
npm install -g @openai/codex
codex

Choose Sign in with ChatGPT (Plus or above), or use an API key.

The loop uses your Codex default model for both agents. Put BRIEF_MODEL=... OPT_MODEL=... in front of a command to change them.

terminal
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.zshrc        # or ~/.bashrc
hermes model

Hermes comes with no model, so the last line picks one. The loop uses it for both agents. A small local model may not keep to the brief's format; the scorer will show you.

Our default was a local model, so for these runs we used Claude Sonnet. These lines apply to every command after them in that terminal:

terminal
export HERMES_PROVIDER=anthropic
export BRIEF_MODEL=claude-sonnet-5-5
export OPT_MODEL=claude-sonnet-5-5

Hermes has no fence while it runs: it can run any command. Run it on this repo and nothing else you care about.

Part 1 · by hand

04Get your saved links

Use links from 30 to 60 days ago. Yesterday's are no good yet: you cannot tell whether they helped. Give a tool that can use your browser this prompt:

copy and paste
Open my bookmarks on X. For every post I saved 30 to 60 days ago, write one row:
the date, who posted it, the post's first line, the link, and the full text of the post
(with any post it quotes). Give me a CSV with the columns: date, source, title, url, text.
Do not judge the posts.

Swap X for Instagram, YouTube, Reddit or your browser history. X does not show when you saved a post, so the post's own date is fine. You get a file like this:

datesourcetitleurltext
2026-10-19Orchard Labs blogPricing update: cached input tokens billed at 10%https://…From 1 November, cached input tokens…
2026-10-20Kiln changelogKiln 2.4: script modehttps://…The agent writes one script…
2026-10-21Anvil securityAdvisory: Anvil plugin sandbox escape, patch nowhttps://…A plugin can escape…

Why the text? A post on X sits behind a login, so an agent that opens the link sees nothing. With the text in the file, it reads the post itself. The columns do not have to match: import reads most exports as they are.

To follow this page first, keep the sample. Your own file comes in step 14.

05Label every link yourself

No agent can do this step for you: it is your judgement going in. On your own links, run this in your own terminal, not through the agent. It shows each link with its text and asks for one key:

Every answer is saved at once. q stops; run it again to carry on. The sample month is already labelled, so skip this for now.

Optional, and worth skipping the first time: your decisions that month in verifier/decisions.csv (date, question, outcome, how_it_turned_out, where the outcome is adopt, wait or ignore).

06A model labels them, blind

terminal
python3 loop.py blank

manual/prompt.txt is weeks 1 to 3 with the labels removed, plus the ask: guess signal or noise for each link. Hand it to a model and save the answer as manual/links-model.csv:

terminal
claude -p < manual/prompt.txt > manual/links-model.csv
terminal
codex exec -o manual/links-model.csv < manual/prompt.txt
terminal
hermes chat -Q -q "$(cat manual/prompt.txt)" > manual/links-model.csv

That uses your Hermes default model. We added --provider anthropic -m claude-sonnet-5-5, to match step 01.

Or paste manual/prompt.txt into any chat window and save the reply. The model sees what you saw in your list: the source and the title. If your titles are only each post's first line, python3 loop.py blank --text gives it the start of each post too.

07Compare

terminal
python3 loop.py compare manual/links-model.csv

Read the two lines under the percentage, not the percentage: 48 of the 75 links are noise, so a model that said "noise" every time would already agree on 64%. Then read the list for the mistake that repeats. Here it was Anvil and Quill DB: their posts sound urgent, but this reader uses neither tool.

Codex agreed on every link. Its session log shows no tool calls: it did not open the labels, it guessed from the titles. The sample's titles are made up and tidy; your own will not be. In Claude Code and Hermes the same file gave two different mistakes: urgent news about tools this reader does not use (Anvil, Quill DB) called signal, and dull titles from the tools they do use ("Kiln 2.4.1", "Vecstore 0.7.3") called noise. 08Write down the mistake, then one rule

The mistake goes in failures.md, with a tag:

failures.md
## F1 · weeks 1 to 3
Saw: the model called four links signal: advisories and removals for Anvil and Quill DB.
Expected: urgent news about a tool I do not use is noise. I use Kiln, Orchard and Postgres with Vecstore.

One rule about that kind of link goes in harness/CLAUDE.md, under What matters to this reader, with the same tag. A tagged rule can be reworded later, never deleted.

harness/CLAUDE.md
The reader uses Kiln, Orchard and Postgres with Vecstore. Urgent news about any other
tool (advisories, removals, "patch now") is noise to them, however loud the title. (F1)

Naming the reader's tools fixes both kinds of mistake from step 07. Go back to step 06: blank puts every tagged rule into manual/prompt.txt by itself, so the model now judges with it.

On your own links, expect several rounds, and expect each rule to move the model's line everywhere, not only on the links you wrote it for. Stop when the disagreements stop teaching you anything. Then commit everything, new files included:

terminal
git add -A
git commit -m "F1: urgent news about tools I do not use is noise"

What just happened

You were the optimizer. Part 2 hands that job to a second agent, and leaves you the labels and the decision to keep a change.

Part 2 · the loop

09Run the first agent

Read harness/CLAUDE.md first. Then let the briefing agent write week 1:

terminal
python3 loop.py brief 1
terminal
RUNNER=codex python3 loop.py brief 1
terminal
RUNNER=hermes python3 loop.py brief 1

Run export RUNNER=codexhermes once and drop the prefix from every command after it.

Score it against your labels:

terminal
python3 verifier/score.py traces/try
the score
(links found + 2 x decisions right - 0.5 x noise called important)
/ (links that mattered + 2 x decisions)

Here: (7 + 4 − 0) / 13 = 0.846.Here: (8 + 4 − 0) / 13 = 0.923.Here: (7 + 4 − 0.5) / 13 = 0.808. Noise costs half a point, or citing everything would win. Any id under What changed or What to do counts, even in a "skip these" line, so a brief that lists what it skipped can score below zero. Ids under Who disagrees are not scored either way.

Now read what it did. The trace is every tool call and what came back:

terminal
python3 loop.py trace traces/try/week-1.jsonl

Look at the fetch.py line. The prompt tells the agent to start with fetch.py --week 1, which prints all 25 links at once. It read every link, and still left 21 of the 9 that mattered out of the brief. Which ones, and why, is what the optimizer looks at next.

10Record the baseline

The score of your setup before any agent changes it. Every round is measured against it. It must be a commit, so step 08's commit comes first.

terminal
python3 loop.py baseline
terminal
RUNNER=codex python3 loop.py baseline
terminal
RUNNER=hermes python3 loop.py baseline

Each week is written three times and the score is the mean. One brief is too small a sample: the same setup can score far apart on the same week. Low to high shows the spread.

11Let the optimizer work

Read optimizer/CLAUDE.md once. Then run one round:

  1. ReportCode picks the worst week and lists every miss.
  2. ProposeThe optimizer reads the traces and makes one change in harness/.
  3. WallsCode checks it stayed in harness/ and kept every tagged rule.
  4. Brief againNine new briefs, scored the same way.
  5. Keep or revertKept only if the mean rose by 0.02 or more.
terminal
python3 loop.py round
terminal
RUNNER=codex python3 loop.py round
terminal
RUNNER=hermes python3 loop.py round

All three optimizers found the same habit: the agent read guides and studies with measured results, then left them out. That is one of the sample's traps, "a thread with real measurements". One rule fixed it, and code kept the change because the mean rose by more than 0.02. See what the optimizer read before it changed anything:

terminal
python3 loop.py trace traces/round-1/optimizer.jsonl

Then more rounds:

terminal
python3 loop.py run 2

Look at the numbers. Rounds 2 and 3 scored 0.979 and 0.983, above the live 0.974, and both were reverted: neither rose by 0.02. That bar is on purpose. A rise smaller than the run-to-run spread may be luck, and kept luck makes the hidden week look worse than it is.

terminal
RUNNER=codex python3 loop.py run 2
terminal
RUNNER=hermes python3 loop.py run 2

A change is kept only if it beats the live score by 0.02. At 1.00.983 nothing can, so the loop stops and sends you to the hidden week instead of spending money on rounds that cannot win. On your own month there is usually more room, and run 5 runs all five.

Every change and every revert is a commit, so git log --oneline is the history and python3 loop.py status the scores. Do not edit files in the repo while run is going: the walls blame the optimizer for any change and revert it. Keep notes in notes/, which git ignores.

12Open the hidden week

A rule that fits weeks 1 to 3 might only fit them. Week 4 has never been shown to either agent. It runs once, and only after a round has been kept: with nothing kept there is nothing to test.

terminal
python3 loop.py final

Week 4 rose, 0.923 to 0.962. Read the of which line: 8.7 of 9 links found instead of 8.0. Then the note: one run of the old setup already scored 1.0, so the rise is inside its own spread. The old setup did well on this week, and some of the gain may be luck.

terminal
RUNNER=codex python3 loop.py final

Week 4 rose, 0.654 to 0.834, and the of which line says why: 8 of 9 links found instead of 5.7, with the same noise. The rule about measured results carried over to a week the loop never saw.

terminal
RUNNER=hermes python3 loop.py final

Week 4 rose, 0.898 to 0.949: 8.7 of 9 links found instead of 8.0. The old setup already did well on this week, so there was less to gain than on weeks 1 to 3.

Always read the of which line before the verdict. If "found" stays the same and only "noise cited" falls, the setup learned what to leave out of a brief, not more about what you value.

Do not compare scores across harnesses. Each starts from its own baseline: compare its before and after.

For a run on real data, the branch real-month holds the real month from step 14 in Claude Code: three rules written by hand, then five rounds, three of them kept. Weeks 1 to 3 went from 0.752 to 0.986 and the hidden week from 0.796 to 0.852, with 8.3 of 9 links found instead of 8.0. Part carried over, part only fit the weeks the loop could see.

The branch is main plus that run's commits: the real month in place of the sample, the rules, the scores and every trace. Read it without switching to it, or it puts its labels and rules in your folder in place of yours:

13When something goes wrong

"run thrown away, Bash reached outside harness/"

The briefing agent looked outside its folder, so the run scores zero. loop.py trace on that run shows the command. A few are normal; if many runs do it, the next round's report shows the optimizer.

A score below zero

The brief cited more noise than it found signal. Every id under What changed or What to do counts as "this matters", even in a "skip these" line.

A round I expected to win was reverted

It has to beat the live score by 0.02. If low to high is wider than the gain, the gain may be luck. RUNS=5 in front gives a steadier number.

"The live score is 1.0: no change can beat it"

Nothing is left to win on weeks 1 to 3. Read the kept changes with git log --oneline, then open the hidden week.

"No change has been kept yet"

final waits until a round is kept, so it does not spend your one look comparing a setup with itself. Run more rounds. To open it anyway: python3 loop.py final --anyway.

A change I made by hand was reverted

You edited a file while run was going. Stop, edit, commit, start again. Keep notes in notes/: git ignores that folder.

"Commit your work first"

git add -A, then git commit -m "...". git commit -am leaves out files you created.

compare: "No row ... has an id"

The model replied with something other than a CSV: a question, a summary or a refusal. Open manual/links-model.csv to see, then run step 06 again.

label: "No keyboard here"

An agent ran it. Run python3 loop.py label in your own terminal.

"Week four is already open"

final runs once, on purpose. To practise again, clone into a new folder.

"The ... run could not reach its model"

The harness had no network or no login, so nothing was scored and nothing was kept: a round it was in is taken back. Usually an agent ran loop.py for you inside its sandbox, and Codex's has no network. Run the same command in your own terminal.

Claude Code: "not logged in", or "this sign-in can end at any time"

Run claude auth login, before a long run so it does not stop halfway. The loop skips your own settings but uses your login.

Codex: the clone or a fetch fails

Clone in your own terminal (step 02). Inside the loop, agents.py turns network on for the briefing agent, so fetch.py works.

Hermes: it hangs or writes nothing

The model is usually not reachable. Start Ollama for a local model, or set a hosted one as in step 01. The first run in a clone also takes one to three minutes to set up.

14Bring your own month

Save your export from step 04 anywhere and bring it in:

terminal
python3 loop.py import ~/Downloads/your-bookmarks.csv

It finds the link, date and text columns whatever they are called, keeps the links from 30 to 60 days ago, and replaces the sample month. To pick the window yourself, add --from 2026-09-24 --to 2026-10-24, or --all. Lines that start with ! are worth a second look: a week with almost no links you acted on gives a jumpy score, and an old outlier date can push most of your links into the hidden week.

Then label, in your own terminal:

terminal
python3 loop.py label

From here the steps are the same, from step 06. Use blank --text if your titles are only each post's first line. python3 loop.py next always says where you are. Your labels live in verifier/links.csv, which is committed in your clone: if your fork is public, so are your bookmarks.

The real month in these screenshots ships with the repo, labelled. python3 loop.py import examples/x-bookmarks.csv --all loads it, so you can try every step on real posts before you export your own. The branch real-month holds a finished run on it, commit by commit; step 12 says how to read it without switching to it.
