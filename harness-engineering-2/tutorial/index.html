Tutorial · Harness Engineering 2.0 · Claude Code, Codex or Hermes

Run the loop yourself.

Every step of the Harness Engineering 2.0 repo, by hand and then with the loop, in Claude Code, Codex or Hermes. Every screenshot is from a real run on the sample month.

This page takes you through the repo from an empty laptop to the hidden week. Part 1 you do by hand. In Part 2 two agents and a few hundred lines of Python take over. The idea behind each step is in the session notes. This page is the how.

We ran every step below on 22 November 2026, on the sample month that ships with the repo, once in each harness. The screenshots are those runs; tap any of them to open it full size. Your numbers will differ a little, because a model never writes the same brief twice.

02Install and log in

Install Claude Code. On macOS, Linux or WSL:

terminal
curl -fsSL https://claude.ai/install.sh | bash

On Windows PowerShell: irm https://claude.ai/install.ps1 | iex. Homebrew also works: brew install --cask claude-code.

Log in. Run claude once and follow the browser prompts. You need a paid Claude plan (Pro, Max, Team or Enterprise) or a Console account. The free plan does not include Claude Code.

Models. The loop uses sonnet for the briefing agent and opus for the optimizer. Change either for one command with BRIEF_MODEL=haiku or OPT_MODEL=sonnet in front of it.

Install Codex. Any one of these:

terminal
npm install -g @openai/codex
brew install --cask codex
curl -fsSL https://chatgpt.com/codex/install.sh | sh

Log in. Run codex and choose Sign in with ChatGPT. A Plus plan or above works. An API key works too.

Models. The loop uses your Codex default model for both agents, read from ~/.codex/config.toml. Ours was GPT-6.1-Sol. To pick others: BRIEF_MODEL=... OPT_MODEL=... in front of a command.

Install Hermes Agent. On Linux, macOS or WSL2:

terminal
curl -fsSL https://hermes-agent.nousresearch.com/install.sh | bash
source ~/.zshrc        # or ~/.bashrc

Pick a model. Hermes is the one harness that does not come with a model. Choose a provider and a model:

terminal
hermes model

The loop uses that default for both agents. A local model through Ollama works only while Ollama is running, and a small one may not keep to the brief's format. Every link it leaves out costs a point, so the scorer will tell you.

What we used. Our Hermes default was a local model, so for these runs we pointed Hermes at Claude Sonnet. These three lines apply to every loop.py command after them in that terminal:

terminal
export HERMES_PROVIDER=anthropic
export BRIEF_MODEL=claude-sonnet-5-5
export OPT_MODEL=claude-sonnet-5-5

Clone it in your own terminal, not from inside the agent. Codex's sandbox has no network by default, so a clone from inside Codex fails.

python3 loop.py prepare

Part 1 · by hand

05Get your saved links

Use links you saved 30 to 60 days ago. Yesterday's links are no good yet: you cannot tell whether they helped. Give a tool that can use your browser this prompt:

copy and paste
Open my bookmarks on X. For every post I saved 30 to 60 days ago, write one row:
date saved, who posted it, the topic in one line, and the link.
Give me a CSV with the columns: date, source, title, url, label.
Leave the label column empty. Do not judge the posts.

Change the first line for Instagram, YouTube or Reddit saves, or your browser history. The file you want looks like this, with the last column empty:

06Label every link yourself

Go down the file and fill the last column. This is the step no agent can do for you: it is your judgement going in.

LabelMeansExample from the sample
signalYou acted on it and it helped. acted means the same.Kiln 2.4: script mode
should haveYou did not act, and now wish you had. Optional.We measured script mode on our nightly batch job: 78% fewer tokens
noiseYou never used it.Advisory: Anvil plugin sandbox escape, patch now (the reader does not use Anvil)
emptyYou cannot tell. The agent still sees the link; it is never scored.

Optional, and worth skipping the first time: verifier/decisions.csv, one row per decision you made that month (date, question, outcome, how_it_turned_out, where the outcome is adopt, wait or ignore).

09Compare

terminal
python3 loop.py compare manual/links-model.csv

Do not stop at the percentage. Read the list and look for the mistake that repeats. In all three harnesses it was the same one: Anvil and Quill DB. Their posts sound urgent ("patch now", "removes the legacy API"), but this reader does not use either tool. A model that does not know the reader's stack calls loud news signal.

10Write down the mistake, then one rule

First the mistake, in failures.md: what you saw, what you expected. Give it a tag.

failures.md
## F1 · weeks 1 to 3
Saw: the model called four links signal: advisories and removals for Anvil and Quill DB.
Expected: urgent news about a tool I do not use is noise. I use Kiln, Orchard and Postgres with Vecstore.

Then one rule about that kind of link, in harness/CLAUDE.md, carrying the same tag. The tag is what stops the optimizer from deleting your rule later: it may reword a tagged rule, never remove it.

harness/CLAUDE.md
The reader uses Kiln, Orchard and Postgres with Vecstore. Urgent news about any other
tool (advisories, removals, "patch now") is noise to them, however loud the title. (F1)

Now go back to step 08. This time give the model your CLAUDE.md with the file, so it labels the way your rules say. We did this with Claude Sonnet:

On the sample, one rule was enough, because the month was built around a few traps. On your own links expect several rounds. Stop when the disagreements stop teaching you anything. Then commit, so the loop starts from your rules:

terminal
git commit -am "F1: urgent news about tools I do not use is noise"

What just happened

You were the optimizer. You read where the agent went wrong, named the pattern, and changed its setup by one rule. Part 2 hands that job to a second agent, and leaves you the two things it may not touch: the labels, and the decision to keep a change.

Part 2 · the loop

11Run the first agent once

The briefing agent reads one week's links and writes a brief in three parts: What changed, Who disagrees, What to do. Open harness/CLAUDE.md and read its instructions first. Then run it on week 1:

terminal
python3 loop.py brief 1
terminal
RUNNER=codex python3 loop.py brief 1
terminal
RUNNER=hermes python3 loop.py brief 1

Tired of typing the prefix? export RUNNER=codexhermes once, and every command after it in that terminal uses it.

Now score it against your labels:

terminal
python3 verifier/score.py traces/try

The score is plain arithmetic, in verifier/score.py:

the score
(links found + 2 x decisions right - 0.5 x noise called important)
/ (links that mattered + 2 x decisions)

Claude Code's brief: (8 + 2×2 − 0.5×3) / (9 + 2×2) = 10.5 / 13 = 0.808.Codex's brief: (6 + 2×1 − 0.5×2) / (9 + 2×2) = 7 / 13 = 0.538.Hermes's brief: (7 + 2×2 − 0.5×3) / (9 + 2×2) = 9.5 / 13 = 0.731. A link counts as found when its id appears under What changed or What to do. Noise costs half a point, because the cheapest way to raise the score would be to cite everything.

12Read what it did

Every run leaves a trace: each tool call, and what came back. Read it before you trust the score.

terminal
python3 loop.py trace traces/try/week-1.jsonl

Each Bash: or Read: line is one tool call. The -> line under it is what came back. Look at the fetch.py line: the agent opened only some of the 25 links, the ones whose titles looked important. That habit is what the optimizer will go after.

The three harnesses log in different formats. agents.py turns each into the same shape, so this command, the scorer and the optimizer read all three the same way. The tool's own log sits next to it as *.raw.jsonl.

13Record the baseline

A baseline is the score of your setup as it is now, before any agent changes it. Every later round is measured against it.

terminal
python3 loop.py baseline
terminal
RUNNER=codex python3 loop.py baseline
terminal
RUNNER=hermes python3 loop.py baseline

It writes nine briefs, three per week, all at once, in about 25 seconds. One brief is too small a sample: the same setup can score 0.46 and 0.89 on the same week. So each week's score is the mean of three runs, and low to high shows how far apart they were. For a steadier number, put RUNS=5 in front.

The baseline is saved in scores.csv and tagged baseline in git. Our Part 2 runs started from the repo's setup as shipped, without the F1 rule, so you can compare yours against them.

14Run one round

One round is five steps. Two of them are a model; the rest is code you can read in loop.py.

  1. ReportCode picks the worst week and lists every miss, with how many runs it happened in.
  2. ProposeThe optimizer reads the report and the traces, and makes one change to harness/, with a reason and a prediction.
  3. WallsCode checks the change stayed in harness/, left permissions alone and kept every tagged rule.
  4. Brief againNine new briefs on the changed setup, scored the same way.
  5. Keep or revertKept only if the mean rose by at least 0.02. Otherwise git revert.
terminal
python3 loop.py round

Read it top to bottom. The optimizer saw the habit from step 12, the agent choosing links by title, and added a rule to read every link. Its prediction names the nine links that rule should fix.

Two things went wrong. Reading every link made the agent cite nearly everything, so noise called important jumped from about 2 to 15. And in all three week-1 runs, the agent's first command looked one folder up (cat ../inbox/week-1.csv || ls ..). Claude Code's permissions blocked it, and the wall threw the run away anyway, scoring it zero. A run that looks outside its folder could have seen the labels, so it does not count. The loop reverted the change. That is the loop working.

terminal
RUNNER=codex python3 loop.py round

Codex's optimizer found a different habit: the agent fetched the right links and then left them out of the brief. It added one rule about covering them. Found went to 9 of 9 in every week. Noise rose a little, from about 1 to 3, but the gain beat the 0.02 bar, so the change stayed as a commit.

terminal
RUNNER=hermes python3 loop.py round

Hermes's optimizer saw the same habit as Claude Code's: links chosen by title. Its fix, read every link, found all 9 links every week, but cited 14 noise links too, and noise costs half a point each. The score fell, so the code reverted it. Notice the agent never decided that itself.

15Read what the optimizer did

terminal
python3 loop.py trace traces/round-1/optimizer.jsonl

The optimizer's instructions are in optimizer/CLAUDE.md. Read them once. It may change only files in harness/, one change per round, and it must give a reason and a prediction. loop.py writes both into optimizer/journal.md, so the next round can see what was tried.

16More rounds

terminal
python3 loop.py run 2

This is the most useful screenshot on the page. Round 2 lost six runs to the same wall. In round 3, the optimizer read those traces and saw the pattern itself: every zero came from a run that looked one folder up. Its rule against that worked, but one run still slipped, and the mean rose only 0.009. That is under the 0.02 bar, so it was reverted too. Three rounds, nothing kept: in our Claude Code run, the setup the repo ships with stayed the best one.

We stopped Codex after one round and went straight to the hidden week. To run more:

terminal
RUNNER=codex python3 loop.py run 3
terminal
RUNNER=hermes python3 loop.py run 2

Round 2 learned from round 1. Instead of "read everything", it named which links matter: first-party notices (changelogs, pricing, deprecations) for products the reader uses. That kept found high without the noise: 0.889, kept. Round 3 added measured guides and papers: 0.940, kept.

Two commands show where you are:

terminal
python3 loop.py status
git log --oneline

Every change is a commit and every revert is a commit, so git show on any round tells you exactly what the optimizer wrote. Do not edit files while run is going: the wall check in step 3 of the round will blame the optimizer for your edit and revert it.

17Open the hidden week

Weeks 1 to 3 are the weeks the loop could see. A rule that fits them might only fit them. Week 4 has never been shown to either agent, or to you. It runs once.

terminal
python3 loop.py final

No change was kept, so both columns ran the same setup. The two week-4 numbers still differ, 0.564 and 0.551, and the three "before" runs ranged from 0.346 to 0.846. That spread is pure chance. Keep it in mind whenever a round "wins" by a few hundredths.

terminal
RUNNER=codex python3 loop.py final

The rule from round 1 helped on a week it never saw: 0.436 to 0.731. That is the result you want. The change captured something about how this reader decides, not something about weeks 1 to 3.

terminal
RUNNER=hermes python3 loop.py final

Week 4 rose from 0.577 to 0.731. It rose less than weeks 1 to 3 did (0.697 to 0.940). Some of the gain was fitted to the weeks the loop could see, and some of it carried over. The hidden week is how you tell the two apart.

18How the three harnesses differ

Everything except the two model steps is the same Python whichever harness you pick. The differences are in how each one is fenced while it runs:

Claude CodeCodexHermes
Fence while it runsA permissions file: it may run only python3 tools/* and python3 scratch/*, and edit only in scratch/Its sandbox: writes only inside the folder, no networkNone: it can run any command
Caught after, by codeThe wallsThe walls, and any setup file a brief changed is put backThe same as Codex
Your own settingsNot readNot read: it gets its own home in .runner/, with your login onlyNot read: its own home in .runner/, with your login and model only
Optimizer's toolsRead, search, edit filesShell, inside its sandboxFile tools only
Cost in the traceDollars and tokensTokensTokens

One file is the setup for all three. Claude Code reads harness/CLAUDE.md itself. For Codex and Hermes, loop.py puts the same file, with sources.md and memory.md filled in, at the top of the prompt. So a change the optimizer makes in one harness reaches whichever you run next.

Run Hermes on this repo and nothing else you care about: nothing stops it while it runs, only the checks afterwards. Hermes normally asks a person before anyone edits a CLAUDE.md. The optimizer's whole job is that edit, so the home in .runner/hermes-home turns that one question off. Your ~/.hermes is not changed.

19When something goes wrong

"run thrown away, Bash reached outside harness/"

A wall. The briefing agent looked outside its folder: .., verifier/, traces/ or optimizer/. Those runs score zero. Open the trace for that run with loop.py trace to see the command. A few are normal. If every run does it, the optimizer will see it in the next round's report, as ours did in round 3.

Codex: the clone fails, or a fetch fails

Codex's sandbox has no network by default. Clone in your own terminal (step 03). The briefing agent's own runs get network turned on by agents.py, so fetch.py works inside the loop.

Codex: the optimizer's trace shows an edit with no text

Codex does not log the text of file edits. Run git show on the round's commit, or git diff baseline -- harness.

Hermes: it hangs, errors, or writes nothing

Usually the model is not reachable. If your default is a local model, start Ollama first. Or pick a hosted model with hermes model, or set HERMES_PROVIDER, BRIEF_MODEL and OPT_MODEL as in step 02. Check the model in Hermes's status bar.

Hermes: the first run is slow

The first run in a clone sets up .runner/hermes-home. It took us from one to three minutes. Later runs take 20 to 60 seconds.

Claude Code: "not logged in", or a sign-in warning

Run claude and log in again. The loop starts Claude Code without your own settings (--setting-sources project), but it uses your login.

A round I expected to win was reverted

A change has to beat the live score by 0.02 (MIN_GAIN in loop.py). Look at low to high: if the range is wider than the gain, the gain may be luck. Run with RUNS=5 for a steadier number.

"Week four is already open"

final runs once, on purpose. A second look is not a hidden week any more. To practise again, clone the repo into a new folder.

A change I made by hand was reverted

You edited a file while run was going. The wall check cannot tell your edit from the optimizer's. Stop the run, edit, commit, then start again.

20Bring your own month

  1. Replace verifier/links.csv with your labelled links. Keep the header row.
  2. Replace verifier/decisions.csv with your decisions, or leave only its header row.
  3. Delete verifier/sample/, harness/sources.md and harness/cache/.
  4. Run python3 loop.py prepare. Days 22 onward become week four.
  5. Do Part 1 at least three times round, then the loop: run 5, then final.

Pages are fetched the first time the agent reads them and kept in harness/cache/, so a week reads the same on every run. Links behind a login, like X or LinkedIn, come back as the title only.
